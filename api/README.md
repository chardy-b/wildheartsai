# Wild Hearts API (Cloudflare Workers)

The Hono backend replacing the Next app's API routes, on Cloudflare Workers with D1. Plan and status: [`docs/superpowers/plans/2026-10-30-cloudflare-migration.md`](../docs/superpowers/plans/2026-10-30-cloudflare-migration.md). Production still runs on Vercel until the cutover.

## Layout

- `src/app.ts`: the Hono app. Every route is under `/api`, at the path the Next app serves today.
- `src/db/schema/`: the main D1 database (binding `DB`), a 1:1 port of the Postgres schema. Table and column names must not change: sealed values are bound to them, and `test/schema-parity.test.ts` checks them against `src/lib/db/*-schema.ts`.
- `src/db/chat/schema.ts`: the chat database (binding `CHAT_DB`), bound only to the chat Worker (`src/chat/`, `wrangler.chat.jsonc`).
- `src/data/scope.ts`: **the only way to reach a person's data.** D1 has no row-level security, so `forUser(db, userId)` adds the owner condition to every query. Route code can't import tables (lint rule in the root `eslint.config.mjs`). `system(db)` is for cross-person jobs. New tables with a person's data go in `USER_TABLES`; `test/user-tables.test.ts` fails otherwise.
- `src/auth/`: Better Auth on D1 (`/api/auth/*`) and `/api/session` for the web Worker (`src/routes/auth.ts`). Email has no provider yet: see `src/auth/email.ts`.
- `src/routes/`: Epic connect (`epic.ts`), records and export (`records.ts`), connections (`connections.ts`), onboarding (`profile.ts`). `src/session.ts` gives each route the signed-in person's scope.
- `src/jobs/`: the background jobs as Workflows (`workflows.ts`): a sync per run (`sync/`), the nightly refresh (`refresh.ts`) and the Epic directory import (`directory/`). Cron Triggers in `wrangler.jsonc` start the daily ones (`src/index.ts`). Run the directory import on request with `npx wrangler workflows trigger wildhearts-directory-<env>`.
- `src/epic/token-refresher.ts`: one Durable Object per Epic connection, so a rotating refresh token is never spent twice.
- Pure modules shared with the Next app (`src/lib/epic/*`, `src/lib/fhir/*`, `timeline-filters`, ...) are imported through `@/`. Don't import anything that pulls in the Postgres schema at runtime or `server-only`; port it into `src/data/` instead.
- `src/crypto/`: the sealing code, ported from `src/lib/crypto/` with identical formats. `test/crypto.test.ts` opens values sealed by the Node code.
- `migrations/`, `chat-migrations/`: generated by `npm run db:generate`, applied with `wrangler d1 migrations apply`.

D1 also allows at most 100 bound parameters per statement: query growing lists with `inSlices` or `inJson`, and write many rows with `bulkInsert` (`src/data/scope.ts`). Transactions work differently on D1. Follow [`docs/superpowers/specs/2026-10-30-d1-transaction-audit.md`](../docs/superpowers/specs/2026-10-30-d1-transaction-audit.md) when porting code that used `db.transaction`, `asUser` or row locks.

## Develop

```bash
cd api
npm ci
cp .dev.vars.example .dev.vars   # then fill in local values
npm run db:migrate:local
npm run dev
```

## Checks

```bash
cd api
npm run typecheck
npm test     # Vitest inside workerd with real D1 bindings; no network or Cloudflare account needed
```

Lint runs from the repository root (`npm run lint`).

## The whole stack on Cloudflare, locally

The web Worker (the Next app through OpenNext, `wrangler.jsonc` at the repository root) and this API Worker run together, the web Worker forwarding `/api/*` over its service binding as in production. From the repository root:

```bash
npm run cf:build           # the Next app for Workers (OpenNext)
npm run cf:migrate:local   # the API's D1 schema, in the shared local state
npm run cf:preview         # both Workers on http://localhost:8787
```

Put local secrets in `api/.dev.vars` (from `.dev.vars.example`), with `BETTER_AUTH_URL` and `EPIC_REDIRECT_URI` on `http://localhost:8787`. `node scripts/qa-cloudflare-walkthrough.mjs <log>` then walks through sign-up, onboarding, records, refresh, delete, export, Documents, the guided demo and (when the edge service runs) live chat in a browser; see the script's header.

### Chat

`cf:preview` also runs the chat Worker (`wrangler.chat.jsonc`, `src/chat/`): one `ChatConversation` Durable Object per conversation running Pi durable, `CHAT_DB` for lists and summaries, and records only through this Worker's `ChatRecords` entrypoint. For answers it needs the VPS edge service on `http://127.0.0.1:8090` (its local `CHAT_EDGE_URL`) and a model behind it. Set `CHAT_EDGE_TOKEN` in `api/.dev.vars`, then from `services/chat`:

```bash
CHAT_SERVICE_MODE=edge CHAT_EDGE_TOKEN_HASH=<sha256 of the token> CHAT_INFERENCE_URL=<OpenAI-compatible base URL>/ CHAT_INFERENCE_MODEL=local-model PORT=8090 npx tsx src/index.ts
```

Chat's tests (`npm test`, project `chat`) run the chat Worker and the API's chat-facing classes in one workerd (`test/chat/wrangler.test.jsonc`) against a scripted model (`test/chat/fake-edge.ts`).
